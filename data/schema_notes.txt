
DATABASE TABLE RELATION NOTES

1. careers
- PK: career_id

2. educations
- PK: education_id

3. specializations
- PK: specialization_id

4. skills
- PK: skill_id

5. certifications
- PK: certification_id

6. career_education_weights
- FK: career_id -> careers.career_id
- FK: education_id -> educations.education_id

7. career_specialization_weights
- FK: career_id -> careers.career_id
- FK: specialization_id -> specializations.specialization_id

8. career_skill_weights
- FK: career_id -> careers.career_id
- FK: skill_id -> skills.skill_id

9. career_certification_weights
- FK: career_id -> careers.career_id
- FK: certification_id -> certifications.certification_id

WEIGHT FORMULA (career profile vectors for CBF):
weight = frequency / total_occurrence_of_career

Interpretation:
- Each career_*_weights table stores attribute importance per career (NOT global SAW weights).
- Used to build career feature vectors in Content-Based Filtering.

RECOMMENDATION PIPELINE:
Input User Profile (education, specialization, skills, certification)
  -> CBF: cosine_similarity(user_vector, career_vector) -> Top-15 candidates
  -> SAW: benefit normalization r_ij = x_ij / max(x_j) on 4 criteria -> weighted sum
  -> Final Top-10 recommendations (score scaled 0-100)

SAW GLOBAL CRITERION WEIGHTS (sum = 1.0):
- skills: 0.40
- certification: 0.25
- education: 0.20
- specialization: 0.15

DATA FLOW:
it_career_dataset.csv -> generate_from_dataset.py -> CSV files -> Laravel seeders -> MySQL
Runtime scoring: Laravel reads DB -> POST JSON payload -> Flask CBF+SAW service
